# 用 Claude Code 做「程式生成的 3D 場景」：流程與提示詞手冊

這份是從聖母院專案整理出來的。換成別的建築、街景或室內場景，照同樣流程做即可。

## 一、整體流程（建議順序）

| 階段 | 做什麼 | 產出 |
|---|---|---|
| 0. 立規則 | 說清楚限制：全部程式生成、不用 3D 模型／貼圖／照片／錄音；固定亂數種子；座標只能來自單一檔案 | 規則寫進第一則提示詞 |
| 1. 平面圖 | 先只做 `layout.js`（所有座標，單位公尺）與 `plan.svg` | 單一座標來源，之後所有模組都讀它 |
| 2. 定光線與時間 | 先問「哪個時間最能看見細節」，再決定太陽方位／高度 | 太陽 247°／19°（春分傍晚） |
| 3. 拆模組 | 切成幾個互不重疊的模組（結構、立面、屋頂、雕刻、環境、人物），每個只改自己的檔案 | 可平行開工 |
| 4. 給參考圖 | 模組骨架出來後再給實景照片，讓它對照修正比例 | 修正（例如鐘塔柱子太長） |
| 5. 檢查腳本 | 寫 `check-modules`：確定性、禁用 API、三角形預算、`update(t)` 只依賴 t | `npm run check` |
| 6. 截圖驗證 | 無頭 Chromium + SwiftShader 拍圖，自己看圖再改 | `tools/shoot.mjs` |
| 7. 影片 | 固定時間步進渲染成逐格圖，再合成 mp4，音訊用離線合成 | 70 秒影片 |
| 8. 互動網頁 | 自由飛行／走路視角、地點跳轉、手機操作說明 | `explore.html` |
| 9. 角色與聲音 | 人物、鴿子、貓狗、山羊、故事角色；Web Audio 合成音樂與鐘聲 | `actors.js`、`audio.js` |
| 10. 雕刻升級 | 重要雕像改用 SDF（有向距離場）雕刻再轉網格 | 近看不再像卡通 |
| 11. 發布 | 獨立靜態網站（本機 three.js）→ GitHub Pages；Claude artifact 另外發布 | 一個可分享網址 |
| 12. 宣傳素材 | 錄操作 GIF、換部落格配圖、寫文章 | `docs/blog/` |

## 二、有效的提示詞

### 開場（一次說清楚限制）
> 用 three.js 做 [地點] 的 [年代] 場景。全部程式生成，不用任何 3D 模型、貼圖、照片或錄音。先做 layout.js（公尺為單位）當唯一座標來源，亂數只能用固定種子。先給平面圖，再開工。

### 先問再決定（讓 AI 提建議）
> 為了看清楚 [細節]，什麼時間／角度最好？請給推薦與理由。

### 拆工
> 把工作切成幾個模組，每個模組只改自己的檔案。列出分工讓我確認再開始。

### 給參考圖時
> 這是實景照片，請對照目前的結果，列出比例或形狀的差異再修正。（附圖，並指出哪裡不對，例如「柱子太長」）

### 要求畫面驗證
> 拍幾張截圖給我看（正面、側面、近景），不要只說完成了。

### 品質升級（很有效）
> [這個物件] 現在太卡通，能不能比照 [已經做好的那個] 的做法再精細一點？
> 其他 [同類物件] 也能比照嗎？

### 聲音微調（用具體數字與時間點）
> 音樂從 0 秒開始；鐘聲約第 11 秒進來，但主旋律不要突然變小聲；整體背景音樂 70%。

### 發布與合併（每次都明講）
> 開 PR 並合併，同步更新網頁。

### 宣傳素材
> 錄一段 10 到 15 秒的網頁實際視角轉動與操作畫面，轉成 GIF，放在文章最前面。

## 三、關鍵技術做法

- **確定性**：渲染只用影格時間，亂數用 `rng('名稱')`，同一份程式永遠出同一張圖。影片渲染才能中斷後續做。
- **三角形預算**：每個模組有上限，超過就調粗取樣或提高預算並寫進 `CONTRACT.md`。
- **SDF 雕刻**：用平滑最小／最大值組合圓錐、橢球、膠囊；Surface Nets 轉網格；去碎片、Taubin 平滑、頂點法線、從場計算 AO；同款物件快取後用 InstancedMesh 重複使用。
- **聲音**：Karplus-Strong 吉他、共振峰合唱、加法合成鐘聲；用 OfflineAudioContext 分段預先渲染，鏡頭移動時才不會卡。
- **螢幕錄影 GIF**：`node tools/record-gif.mjs`。用假時鐘讓每格固定 0.1 秒，軟體渲染再慢，動作速度仍然正確；要用本機 three.js 的 `index.html`（`explore.html` 走 CDN，沙箱連不出去）。偶發的黑格可用前後兩格混合補起來。
- **獨立網站**：`npm run site` 產生 `index.html` 與 `vendor/three`，加 `.nojekyll`，GitHub Pages 選 main／root。

## 四、踩過的坑

| 問題 | 解法 |
|---|---|
| 背景任務超過 2 小時被砍 | 渲染器做成可續跑，每次存部分影片 |
| 舊程序繼續寫舊畫格 | 殺程序時用精確的 pkill 條件；重跑前刪掉舊畫格 |
| 音樂在鏡頭移動時卡頓 | 音樂與鐘聲離線預先渲染 |
| 鐘聲聽不出來 | 提高八度或回原音高，依你的偏好決定 |
| Math.hypot 太慢 | 自己寫 hypot；做區域剔除 |
| SDF 背面剔除出現針孔 | 用組合式的繞線規則 |
| 三角形超預算 | 調粗 H（取樣格距）或提高預算 |
| 嘴巴雕刻切斷下顎，留下漂浮碎片 | 縮小雕刻體積、避免切穿 |
| CDN 在沙箱載不到 | 用本機 vendor 版 three.js |
| GitHub 合併工具 | 要完整 40 字元的 `expectedHeadSha` |
| 無頭截圖偶發黑格 | 檢查每格亮度，異常格用鄰格混合 |

## 五、做新樣本時的檢查表

1. 先決定主題、年代、光線時間。
2. 第一則提示詞寫明限制與座標來源。
3. 先出平面圖，確認後才分模組。
4. 每個模組完成就跑檢查並截圖。
5. 拿到參考圖再做比例修正。
6. 先做可互動網頁，再做影片（影片很耗時，約 7 小時）。
7. 精細雕刻放最後，用「比照已經做好的那個」的說法最有效。
8. 發布前確認用本機 three.js，不依賴 CDN。
9. 每次合併前自己說「開 PR 並合併」，AI 不會主動合併。
